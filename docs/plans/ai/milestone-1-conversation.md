# Milestone 1 — conversation

**Outcome:** you mention munibot in Discord and he answers, in character, streaming his reply, using
tools when he needs them, staying inside a cost budget.

This milestone builds the entire foundation: types, provider abstraction, tool system, agent loop,
context management, persona configuration, and one platform adapter. Nothing here is throwaway —
milestones 2 through 5 add to it rather than replace it.

**Phases 0 through 8, commits 1 through 66.**

## Pre-flight checks — done

Completed before any implementation work. Full results in
[`docs/notes/ai-preflight-findings.md`](../../notes/ai-preflight-findings.md).

Two assumptions were wrong and this milestone has been corrected accordingly:

1. **`rig-core` 0.41 has no `DynClientBuilder`**, and its `CompletionModel` is **not object-safe**
   (associated types, a `Clone` supertrait, and `impl Future` returns). Runtime provider selection is
   a hand-written match over a generic adapter instead. Verified by compilation.
2. **rig has no per-provider feature flags.** All 26 providers compile unconditionally, so
   `munibot_ai_provider` cannot forward feature flags to rig.

Everything else passed: rig-core and bollard both build on `rustc 1.99.0-nightly (2026-07-24)`, the
low-level tool-calling and streaming APIs have everything the harness needs, and rig introduces no new
dependency version conflicts. Two items remain unverified — podman is not installed, and no Exa key was
available, so Exa's shape comes from its OpenAPI spec rather than a live call.

### Crate consolidation

Commits 4 through 22 below were originally executed as two standalone crates, `munibot_ai_types` and
`munibot_ai_provider`. A `refactor(ai): consolidate ai crates into a single munibot_ai crate` commit
later folded both into `types` and `provider` modules of one `munibot_ai` crate — a project this size
does not need ten `Cargo.toml`s, and Rust's module privacy enforces the same internal boundary a crate
split would. This document describes the consolidated structure directly; a reader checking `git log`
will see the crate-creation commits followed by that refactor rather than modules appearing from
nothing.

`munibot_toolagent` and `munibot_vcs`/`munibot_github` (phases 14 and 15) stay separate crates — see
`docs/plans/ai/overview.md` for why.

## Phase 1 — `ai::types` module

Provider-neutral domain types. No I/O, no async, no HTTP. Everything else in the system speaks these
types, which is what makes the provider swappable.

Every type derives `Serialize`, `Deserialize`, `Clone`, `Debug`, and `PartialEq`. Types that cross
into a tool schema also derive `JsonSchema`. Every commit adds colocated roundtrip tests.

## Definition of done

- Mentioning munibot in a Discord channel produces a streamed, in-character reply.
- `/ask persona:researcher` runs a multi-step tool loop with visible progress and cites its sources.
- A missing API key produces a clear startup error naming the variable, not a panic mid-conversation.
- Exceeding a budget truncates gracefully with a marker instead of erroring.
- `devenv test` passes with no network access.
- Setting `ai.enabled = false` removes the feature completely.

## Deliberately deferred

Conversation history does not survive a restart, there is no per-user memory, no auto-routing, no
Twitch support, and no settings interface. Those are milestone 2. Resisting them here is what keeps
this milestone shippable.
